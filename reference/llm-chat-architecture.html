LLM chat architecture

A chat UI is a coordinated loop, not just a textbox connected to a model.

1. User message
Browser sends text plus conversation ID to your backend.
2. Authenticate and scope
Verify identity; resolve tenant_id and role server-side. Never trust tenant IDs in the body.
3. Retrieve context
Fetch tenant-scoped cloud facts, runbook text, and conversation history. Retrieved facts are fresher than model memory.
4. Let the model choose
The model predicts either a direct response or a structured tool call such as cost.get_costs.
5. Execute safely
Backend validates the tool, tenant, role, arguments, timeout, and read-only policy; then calls AWS/MCP.
6. Synthesize and stream
Send text and evidence incrementally to the UI. Render tool activity and citations distinctly from prose.

Trust boundaries

Model output is untrusted text. Tool wrappers enforce authorization. Database queries, vector collections, and Vault paths must all be tenant-scoped.

Vocabulary

Token: a small text unit. Context window: tokens available for one request. Embedding: a vector used to find related text. Grounding: supplying evidence to constrain an answer. Tool calling: structured model-selected actions executed by your server.
